# Индексирование текстов — экзамен, вариант 02

Проект реализует **задания 02, 03, 04, 07 и 11** на Python. Все задания запускаются независимо, как требуется в экзаменационном варианте.

Тематика корпуса: **история и культурное наследие** — археология, архитектура, живопись, история литературы.

## Что реализовано

### 02. Морфологическое индексирование
- три независимых представления: словоформы, стемминг, лемматизация;
- `term -> список doc_id`;
- одинаковая нормализация корпуса и запроса;
- поиск по объединению списков терминов;
- ранжирование по числу различных совпавших терминов, затем по `doc_id`;
- два эксперимента: со стоп-словами и без них;
- Precision@5, Recall@5, размер словаря, доля OOV-терминов запросов;
- исходный текст сохраняется;
- даты не лемматизируются и не объединяются;
- отдельный пример исторической/современной формы (`град` / `город`).

### 03. Позиционный индекс и язык запросов
- индекс `term -> doc_id -> позиции` с нуля;
- булевы операторы и скобки;
- приоритет: `NEAR/k` -> `NOT` -> `AND` -> `OR`;
- точные фразы в двойных кавычках;
- упорядоченный `NEAR/k`: правая позиция должна быть после левой, расстояние `1..k`;
- `NOT` вычисляется относительно актуального множества документов;
- добавление/изменение/удаление документа без полной перестройки;
- независимый последовательный просмотр как эталон;
- маленький корпус и 20 заранее заданных проверок;
- даты и названия рядом (`Царьград AND 1453`).

Примеры синтаксиса:

```text
музей AND NOT обзор
"культурное наследие"
археология OR (архитектура AND NOT реставрация)
Петроград NEAR/3 1917
```

`NEAR/k` в этой реализации намеренно принимает **TERM NEAR/k TERM**. Это явно зафиксированное ограничение синтаксиса, чтобы позиционная семантика была однозначной.

### 04. Сжатие и ускорение индекса
- списки вхождений строятся внутри задания;
- delta-кодирование;
- Variable Byte реализован вручную;
- 7 младших бит — данные, старший бит последнего байта равен 1;
- проверяются `0`, `127`, `128`, большие ID, пустой список;
- декодер обнаруживает обрезанную последовательность;
- baseline — `uint32`, 4 байта на ID;
- обычное пересечение двумя указателями;
- пересечение с пропусками;
- сжатый список с точками возобновления декодирования (checkpoints);
- синтетические списки до 100 000 ID и несколько плотностей пересечения;
- измеряется медиана времени по нескольким повторам;
- в память сжатого варианта включается стоимость checkpoint-структур.

### 07. Дубликаты и близкие тексты
- словесные шинглы 2/3/5;
- Jaccard реализован вручную;
- MinHash реализован вручную, стабильное хеширование через `blake2b`, фиксированный seed;
- подписи 64/128;
- генератор копий и небольших правок сохраняет связь с исходным документом;
- 60 размеченных пар: копии, правки, тематически похожие и несвязанные;
- отдельный отрицательный пример с общей цитатой;
- порог подбирается только на `tune`, итоговые метрики — только на `test`;
- precision, recall, F1, абсолютная ошибка MinHash относительно Jaccard, время;
- документы одного исходного источника не разрываются между `tune` и `test`.

### 11. Опечатки и именованные сущности
- 60 запросов: корректные, обычные опечатки, ошибки в сущностях, редкие правильные названия;
- половина данных для настройки, половина для проверки;
- словарь словоформ `слово -> частота` строится по корпусу;
- справочник `PERSON/ORG/LOC` строится только по данным настройки;
- Левенштейн реализован вручную;
- пороги 1 и 2;
- tie-break: меньшее расстояние -> большая частота -> алфавит;
- два NER-подхода:
  - справочник;
  - готовая русскоязычная модель spaCy `ru_core_news_sm`;
- четыре комбинации: A/B × справочник/spaCy;
- A: коррекция -> NER;
- B: NER -> защита найденных сущностей -> коррекция -> повторный NER;
- оценка top-1 исправления, доля повреждённых корректных слов, точный F1 сущностей по границам и типу;
- журнал замен;
- перенос эталонных границ после изменения длины строки;
- каталог сущностей `type -> name -> doc_id`;
- отдельный случай омонимии `Пушкин` как фамилия и как название города.

# 3. Подготовка корпуса

## Вариант A — для сдачи: научные публикации через OpenAlex

Скрипт собирает русскоязычные научные статьи/метаданные с аннотациями по тематике варианта и сохраняет источник каждого документа.

```powershell
python scripts/fetch_openalex.py --limit 220 --out data/corpus.jsonl
```

Если преподавателю нужны именно **полные тексты**, а не аннотации, используйте бесплатный API-ключ OpenAlex и режим GROBID full text:

```powershell
$env:OPENALEX_API_KEY="ваш_ключ"
python scripts/fetch_openalex.py --limit 220 --fulltext --out data/corpus.jsonl
```

При наличии ключа OpenAlex можно передать его через переменную окружения; скрипт также поддерживает `OPENALEX_MAILTO`:

```powershell
$env:OPENALEX_API_KEY="ваш_ключ_если_есть"
$env:OPENALEX_MAILTO="your_email@example.com"
python scripts/fetch_openalex.py --limit 220 --out data/corpus.jsonl
```

Без ключа скрипт также пытается использовать публичный API, но действующие лимиты OpenAlex могут меняться.

После загрузки **просмотрите корпус вручную** и удалите документы, не соответствующие тематике. Для задания 04 должно остаться не менее 200 документов, для 02/03 — не менее 120, для 07 — не менее 100.

> Важно: преподаватель требует самостоятельно найденные научные тексты. Скрипт OpenAlex предназначен именно для экзаменационного набора. `build_demo_corpus.py` ниже — только офлайн-проверка кода.

## Вариант B — офлайн smoke-test

```powershell
python scripts/build_demo_corpus.py --count 220 --out data/corpus.jsonl
```

Этот корпус синтетический и **не должен заменять научный корпус на защите**.

# 8. Формат корпуса

Одна строка JSONL = один документ:

```json
{"doc_id":"D0001","title":"...","text":"...","language":"ru","topic":"археология","source":"https://..."}
```

Обязательны `doc_id` и `text`. Для экспериментов желательно сохранять `title`, `topic`, `source`, `year`, `language`.

# 9. Что показать на защите

Подробный список находится в `REPORT_GUIDE.md`. Минимально:

1. **02:** одно слово в нескольких формах и один неоднозначный/исторический пример; сравнение трёх режимов.
2. **03:** AST одного сложного запроса, позиции терминов, затем изменение документа без полной перестройки.
3. **04:** вручную декодировать один Variable Byte список, показать delta и объяснить, когда skip помогает.
4. **07:** вручную построить шинглы маленькой пары и объяснить, почему общая тема/цитата не равна дубликату.
5. **11:** редкое правильное имя, опечатку в сущности, работу A/B и сдвиг диапазона после коррекции.
